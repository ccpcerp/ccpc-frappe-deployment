## 2. E1 modeled callback-ordering tests: exact limitations

The [offline tests](../../tests/offline/test_material_issue_precommit_effects_20261016.py) use **small, deliberately reduced Python models derived from the pinned call paths**; they are **not copies of entire upstream modules and do not import a running Frappe, ERPNext, CCPC app, Docker, Redis or SQL driver**. For example, the model replaces `frappe.cache` and DB transactions with in-memory event lists and uses a synthesized minimal Stock Entry object. The snippets and their source pins must be reviewed together; these tests cannot independently assert the complete upstream source, installed version or actual network behavior.

Coverage contract: simulated permission/row-lock/duplicate-draft/insert/submit order and injected failures; immediate cache clearing before deferred callbacks; full COMMIT versus full ROLLBACK versus savepoint behavior; immediate, deferred, duplicate, rollback-discarded and task-progress realtime publication **in the model**; callback failures after a synthetic commit; no external imports/IO. All names and events synthetic. **A passing E1 test result must be reported `OFFLINE_ORDERING_PASS` only**, never `REDIS_ISOLATED`, `WORKER_ROUTE_OK` or `POSTING_ALLOWED`.

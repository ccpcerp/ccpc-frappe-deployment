## 2. Pinned-source transaction lifecycle findings

**T1 — The builder commits the entire open transaction, not solely its own rows: BLOCKER until the invocation procedure is reviewed.** Pinned Frappe [`frappe/database/database.py`](https://github.com/frappe/frappe/blob/988e54f3c4c291e2077a83809663f123731abe76/frappe/database/database.py) has `Database.commit()` issue SQL `COMMIT` (and begin the next transaction), with before/after-commit callbacks. `Database.rollback()` issues SQL `ROLLBACK` (and begin next transaction), with callback hooks. A savepoint is not a nested independent commit and does not undo non-DB side effects. The builder checks the Finance CI identity, two opt-in flags, canonical masters and fresh group, then uses genuine finance methods, and finally calls `frappe.db.commit()`. **But its statement that the caller owns a fresh transaction is an assumption, not a runtime-verified invariant.** The caller must be a fresh disposable bench command with no preceding uncommitted work; an unrelated dirty transaction would be committed too. A separate bootstrap and explicit clean transaction boundary must be designed and peer reviewed before invoking. It is not appropriate to call from the existing `ERPNextTestSuite` transaction.

**T2 — Ordinary ERPNext test fixtures are rollback-managed: verified.** Pinned ERPNext [`erpnext/tests/utils.py`](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/tests/utils.py) defines `ERPNextTestSuite.tearDown()` to `frappe.db.rollback()` and `load_test_records(self,doctype)` via `load_test_records_for(doctype)`. Current CCPC `test_finance_lifecycle_disposable_integration.py` loads `Stock Entry` test records then inserts synthetic roles/users/mappings in that rollback-managed test. The new two-connection business-race probe intentionally begins with a rollback before starting independent worker transactions. **Uncommitted/test-rolled-back Maker/Checker and mapping decisions are not a valid concurrency fixture.**

**T3 — Genuine service sequencing is source-consistent but not database-proven.** The new builder verifies an exact fake Company/Expense Account, creates synthetic Maker/Checker and Company-scoped User Permissions, calls real `propose_mapping`, `get_mapping_review`, `sign_mapping_decision` and, for a separate Retire fixture, `approve_mapping`, `request_mapping_retirement`, `get_retirement_request_review`, and another real `sign_mapping_decision`. It leaves one signed unconsumed race decision, commits the fixture, and returns `action, target, expected_modified, decision_id` matching `verify_finance_business_race` inputs. Source has no old test-only SQL transition of a Draft to Approved. **Runtime behavior remains unverified** for role controller hooks, Session user switch, Company User Permission effects, signed-decision digest, old/new unique indexes, and Version/audit callbacks.

**T4 — The builder is not a hermetic transaction-guarded initializer yet.** Preflight refuses existing target Item Group but does not prove the entire disposable DB is pristine, nor that no unrelated caller transaction is pending. It checks `Company`, `Account` and `Item Group` existence but does not create canonical prerequisite masters. It uses ordinary Frappe `User` insert/save hooks; `send_welcome_email=0` reduces one expected notification path, but does not independently attest all other possible hooks or external integrations. A future test harness must prove network/secret isolation and prevent user notification/external side effects. Rollback on exceptions works for transactional DB effects only; any non-DB callbacks/files must be separately assessed.

## 3. Pinned ERPNext test-master facts and gating

- Pinned [`erpnext/stock/doctype/stock_entry/test_records.json`](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/stock/doctype/stock_entry/test_records.json) uses `_Test Company` and `Stock Adjustment - _TC` in Stock Entry test rows; pinned [`test_stock_entry.py`](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/stock/doctype/stock_entry/test_stock_entry.py) calls `load_test_records("Stock Entry")`. Their presence in **test data** is not proof of pre-existing committed masters on a newly installed disposable site.
- The fixture builder's explicit prerequisites are `_Test Company`, `Stock Adjustment - _TC` as a non-group, enabled Expense Account belonging to that Company, and `All Item Groups`. It does not bootstrap them. Pinned ERPNext test helpers and dependencies can prepare test data **only through an independently reviewed, site-guarded setup procedure**, not by running arbitrary test modules or passing through a persistent database.
- For a valid future two-transaction test, existing master rows, Maker/Checker roles, scoped users, fictional group and independent signed decision must be **committed within the disposable site**, and must be visible from each worker's separate DB session. Approval and Retire use **different** canonical synthetic groups/decisions. A previously consumed decision, stale modified token, missing permissions, or an unexpected duplicate must produce a failed test, not automatic fixture recreation/retry.
- Verify migrated MariaDB `SHOW INDEX` / equivalent read-only metadata for unique `CCPC Mapping Decision Use.decision`, `CCPC Accounting Mapping Decision.decision_key`, `CCPC Mapping Retirement Event.decision`, `retirement_request`, `target_key`, and `CCPC Mapping Retirement Request.request_key`. Do not assume DocType `unique` JSON proves the physical database index exists until an isolated migrated schema is inspected.

**Finding:** Prerequisite preparation is **not implemented in the current Finance CI YAML**. A disposable Finance site is created and migrated before the existing eight tests, but no explicit synthetic master bootstrap / separate fixture commits / local web listener / HTTPS-cookie session establishment / new probe invocation exists. **Thus the current source is not ready for a one-run Finance HTTP/CSRF and concurrency integration claim.** The original 8-test Finance suite is a distinct, smaller candidate after G2 safety authorization.

## NEW policy transition safety contract

The new standalone Python code uses only the existing root-only R0 manifest at `/var/lib/ccpc-new-a3-r0-manifest-20261113/manifest.json`, without printing, modifying or recapturing it. It requires root via named sudo operator `ccpcadmin` on `ccpcerp-prod`, rejects remote/context Docker overrides, and accesses only local socket `unix:///var/run/docker.sock`.

The `--check` mode reads metadata only. The `--apply` mode is **mutating** and may only proceed when the six original candidates are all running with `RestartPolicy=no`; 19 immutable full IDs and expected running/exited statuses match, the other 13 policies remain `no`, pinned candidate images/network/volumes/frontend bridge IP and internal-network members match, DB is healthy, and none of six has host-published ports. Each step uses `docker --host unix:///var/run/docker.sock update --restart=unless-stopped <one full pinned container ID>` and re-inspects all 19 identities and network before the next candidate. **No Docker Compose, create, pull, start, stop, restart, build, exec, DB/site mutation or backup restore.** Switching restart policy metadata is not the same as validating automatic recovery.

The `--compensate` mode is also **mutating** and requires an explicitly reverified *strict candidate-prefix state* (earlier candidates `unless-stopped`, the remainder `no`, 13 noncandidates untouched). It restores those exact earlier candidate IDs in reverse order to `no`; it does not stop services or change volumes. **Do not run automatically after an ambiguous failure.** If the Docker update times out, current state drifts, or a non-prefix policy appears, the tool prints only sanitized `CCPC_NEW_A3_G1_POLICY_POSSIBLE_PARTIAL_STOP_REVIEW_REQUIRED` and stops without blind retry/rollback. A fresh review is needed before compensation; it may be impossible to run after reboot because it intentionally requires the protected pre-boot 19-container running-state baseline.

**Limits:** This tool does not prove NEW business-write isolation, staff reachability, actual worker/scheduler absence at future restart, Caddy health, OLD pause/freeze, or post-reboot recovery. It is a narrow identity-pinned policy metadata executor, not a cutover or safety certifier. The current owner-reported one-time NEW process observation (backend three processes, no recognized worker/scheduler signatures) and Redis DB0 zero-key observation are limited point-in-time evidence.

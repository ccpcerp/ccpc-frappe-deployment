## Findings tied to source

1. **Issue-side allocation must be verified first.** The [CCPC Material Issue builder](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/withdrawal_slip_stock.py) (`_build_material_issue`) sets the source company, warehouse, quantity, provenance and Equipment where present. It does **not explicitly set** row `expense_account`, `cost_center`, or beneficiary `department`. The Withdrawal Slip's `department` is the requesting Department; `work_for_department` can represent the beneficiary. `equipment_costing.set_equipment_defaults` derives Department from Equipment when appropriate, **not necessarily the original beneficiary**. These are potential attribution mismatches; no claim of actual deployed misposting follows from source inspection alone.
2. **Native ERPNext GL path:** Pinned [Stock Entry](https://github.com/frappe/erpnext/blob/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/stock/doctype/stock_entry/stock_entry.py) fills missing item-row expense accounts and Cost Centers using defaults. Pinned [StockController.get_gl_entries](https://github.com/frappe/erpnext/blob/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/controllers/stock_controller.py) creates the stock asset / row expense-account pair using the actual Stock Ledger `stock_value_difference` and item-row `cost_center`. Incoming stock normally implies the opposite sign to Material Issue. Pinned [AccountsController.get_gl_dict](https://github.com/frappe/erpnext/blob/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/controllers/accounts_controller.py) propagates only **configured accounting dimensions** from voucher/item data. Therefore carrying Equipment as a custom field does **not by itself** prove a GL Equipment dimension. We must inspect actual configured Accounting Dimension records and real GL rows in a separately authorized test target.
3. **Do not reuse issue-only provenance unchanged.** [`validate_withdrawal_slip_stock_entry`](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/withdrawal_slip_stock.py) rejects a `withdrawal_slip`-linked Stock Entry unless its purpose is `Material Issue`. The new Material Receipt needs its **own separately validated and immutable return-source links**, not a relaxation that permits arbitrary receipts against the original issue. `sync_withdrawal_slip_issue_status_for_name` currently reads stored `returned_qty` for net use but does **not derive it from posted linked return vouchers**. The Slip Item's `returned_qty` is marked read-only in JSON, yet the server-side stockroom-controlled field tuple does not include it; the effective UI/API and DocPerm behavior needs testing, not assumptions.
4. **Roles cannot be inferred from business titles.** The [Withdrawal Slip JSON](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/doctype/withdrawal_slip/withdrawal_slip.json) grants DocPerms to `System Manager`, `Maintenance Supervisor`, `Stockroom Personnel`, and `Withdrawal Slip Requestor`. This does not prove a configured `Stockroom Supervisor` role, particular user assignments, or Stock Entry approval/cancellation authority. Existing issue submission checks `Stockroom Personnel` and issuer/preparer separation; [`_require_stockroom_user`](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/withdrawal_slip_stock.py) has a separate `System Manager`/Administrator path. The new **approved two-person return verification and supervisor submission/cancellation policy** must be enforced distinctly on POST/API/voucher hooks and checked against actual company/warehouse rights.
5. **The current genuine integration test does not settle expense attribution.** [`test_withdrawal_real_ledger_integration.py`](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/doctype/withdrawal_slip/test_withdrawal_real_ledger_integration.py) checks issue quantity, SLE inventory decrease, Bin quantity, total debit-credit balance and successful **original issue** cancellation. It does **not assert exact debit expense account, Cost Center or Equipment dimension**, nor linked separate receipt postings. The earlier [79/79 PASS CI](https://github.com/ccpcerp/ccpcerp/actions/runs/38900855857) remains valid for its existing scope only.
6. **Cancellation safety:** ERPNext Stock Entry `on_cancel` uses stock ledger and reversing GL entry machinery; this does **not** prove that a new return cancellation is safe when accepted stock was later reissued, or that source-issue cancellation is blocked while active returns exist. Enforce the previously owner-approved link-dependent cancellation block **before** cancelling the source issue; a return cancellation must reverse **only** that return and recompute accepted quantities. Add synthetic tests for depleted returned stock, financial-period restrictions, retry/replay, and concurrent partial receipts/cancellations.

## Pinned source findings

1. **Company/controller supports expected Standard CoA, but runtime is unverified.** The pinned ERPNext [Company controller](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/setup/doctype/company/company.py) `validate_coa_input()` sets Standard Template and `on_update()` calls `create_default_accounts()` when none exist; the latter invokes `create_charts(self.name, self.chart_of_accounts, self.existing_company)`. [The Standard chart](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/accounts/doctype/account/chart_of_accounts/verified/standard_chart_of_accounts.py) includes the leaf `Stock Adjustment` under `Expenses`, with account type Stock Adjustment. [The account controller](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/accounts/doctype/account/account.py) delegates naming to [`get_autoname_with_number`](https://github.com/frappe/erpnext/blob/4048fb70e14d1843956fcdabb7c3cca75a1cbcdd/erpnext/accounts/utils.py), which attaches the Company abbreviation. Hence `Stock Adjustment - _TC` is **supported by the pinned source design**, not a proven committed account on a disposable live site. The new bootstrap still must fail closed if controller behavior differs, if its dependencies are missing, or if hooks fail.
2. **Caller flag contamination risk found.** The same pinned Company controller sets `frappe.local.flags.ignore_root_company_validation = True` within `create_default_accounts()`; `on_update()` sets `frappe.flags.country_change = True`. These are Frappe **thread-local context flags**, not DB transaction rows. Pinned Frappe [`frappe.__init__.py`](https://github.com/frappe/frappe/blob/988e54f3c4c291e2077a83809663f123731abe76/frappe/__init__.py) initializes `local.flags` during `frappe.init()`, while `connect(set_admin_as_user=False)` creates a DB connection and `set_user()` resets user/session caches **without resetting `local.flags`**. Current PR22 `ci_finance_setup_connection.py` restores original DB/user but does **not** snapshot/restore flags. After synthetic Company creation, a long-lived caller may retain permissive flags even after child DB rollback/close. This is an **identified source-level isolation gap**, not a reproduced exploit or observed production issue. Before runtime bootstrap, review and address context restoration with focused offline tests or restrict execution to an independently clean, short-lived disposable process and document the residual state risks. Do not assume restoring the DB pointer restores all Frappe state.
3. **Unique metadata declared, physical indexes not checked.** On the PR22 review branch, DocType JSON declares `unique: 1` for `CCPC Mapping Decision Use.decision`, `CCPC Accounting Mapping Decision.decision_key`, `CCPC Mapping Retirement Event.decision`, `.retirement_request`, `.target_key`, and `CCPC Mapping Retirement Request.request_key`. These source definitions **do not prove** the MariaDB indexes are present after a real disposable-site migration. Require read-only metadata verification on the separately authorized isolated Finance database before approving business concurrency acceptance.

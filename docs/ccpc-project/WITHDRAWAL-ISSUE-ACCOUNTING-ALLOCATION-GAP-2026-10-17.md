This document is a diagnostic and proposed decision path, not authorization to alter GL posting rules.

[Draft app PR #14](https://github.com/ccpcerp/ccpcerp/pull/14) extends the real-ledger integration test to create an original Withdrawal Slip with **different requesting and beneficiary Departments**, an Equipment Registry item belonging to the beneficiary Department, and an otherwise legitimate issued Material Issue. In first isolated [CI run 39031486539](https://github.com/ccpcerp/ccpcerp/actions/runs/39031486539), all **72 mock tests** passed, while the **8 real database integration tests had 6 passes and 2 failures**.

The Equipment field was **not configured on the disposable site's GL Entry**, so it could not be asserted. The tested charge amounts and row Cost Center were internally reconciled. The test failure is deliberately left visible. This is **not evidence** that any real CCPC site's Department postings are wrong; target configuration has not been accessed.
- **Concurrent issuer failure (test harness):** Initial worker's exact branch guard rejected the new PR branch, before meaningful concurrency testing. The worker's allowed CI head refs were narrowly extended on [test-only commit `e2556459`](https://github.com/ccpcerp/ccpcerp/commit/e2556459eb62d585f5c92f1b5d9d0e42312a46c8); no financial posting code was changed. ## Source-backed mechanism

1. CCPC [`_build_material_issue`](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/withdrawal_slip_stock.py) provides `Stock Entry.company`, source warehouse, Item and issue quantity, plus header/row Equipment **only if those custom fields exist**. It does **not** assign `expense_account`, `cost_center`, or `work_for_department`/Department on the issue rows.
2. Pinned [ERPNext Stock Entry and Stock Entry Detail JSON](https://github.com/frappe/erpnext/tree/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/stock/doctype) contain native Cost Center and/or expense-account row fields, but **no native `equipment` or `department` fields** on either Stock Entry or Stock Entry Detail. Such dimensions need a verified, compatible custom/Accounting Dimension configuration, not a guessed setter in the app.
3. Pinned [ERPNext StockController.get_gl_entries](https://github.com/frappe/erpnext/blob/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/controllers/stock_controller.py) uses the source Stock Ledger value difference and the row expense account and Cost Center. [AccountsController.get_gl_dict](https://github.com/frappe/erpnext/blob/5af6561f5aa48104559692fb4fd82f2580e8d338/erpnext/controllers/accounts_controller.py) propagates **configured Accounting Dimensions** from voucher/item. A field on the source Equipment Registry or Withdrawal Slip alone does not guarantee a GL dimension.
4. CCPC [`equipment_costing.set_department_from_equipment`](https://github.com/ccpcerp/ccpcerp/blob/6aea58f9d785f037076b75bc9e0b4bc7bf683bd2/ccpcerp/ccpc_erp/equipment_costing.py) fills missing Department from Equipment where supported, and the Slip itself distinguishes `department` (requester) from `work_for_department` (beneficiary). When they differ, the beneficiary must be explicitly validated and preserved in the intended accounting allocation; **no unapproved fallback** to requesting Department or current Equipment department.
5. Existing `CCPC Operational Supervisor` is a shared **operational supervisor** role; `Department Manager` is separate. Owner confirmed `Department Supervisor` was just a suggested unused name. **No role rename**; neither existing general role automatically grants stockroom return approval/cancellation authority.

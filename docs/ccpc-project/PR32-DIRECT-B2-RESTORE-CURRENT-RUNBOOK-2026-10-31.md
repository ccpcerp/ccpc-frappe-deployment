These must be one matched pair from a **short-lived, read-only, single-bucket, exact-prefix** B2 application key. Do **not** use a master key, grant write/delete, or expand bucket permissions. `CCPC_RESTORE_OBJECT_GET_URL` must **not** be used. No downloading links, Boto3/presigning or Windows clipboard handoff will be required for the new workflow.
5. The job authorizes via B2 Native API v4, validates the token's 7-day-or-less remaining expiry, `readFiles`, exact bucket ID/name-prefix and S3 region, then downloads **one exact private age ciphertext** via the token in an HTTPS header, with redirects/proxies disabled. It verifies fixed ciphertext size and SHA-256 before persisting encrypted-only bytes (0700 scratch / 0600 file). All pre-restore source, site, DB and manifest attestation stays unchanged. No DEV or PROD access.
6. A real restore remains **untested**. Sanitized test results must be reviewed; stop on first failure and never automatically retry. After final one-time result, remove both B2 variables and age identity from the restricted context, revoke the temporary B2 key, and retire the context when safe. Preserve original Ubuntu/NAS recovery copies; any B2 object cleanup requires separate review and exact version scoping.
